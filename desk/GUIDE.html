mcproxy desk

The desk app on your computer shows everything your mcproxy knows, live: the companion, the mesh, the channels and your chats.

Overview

mcproxy runs on a small machine next to your MeshCore companion radio and records everything it hears. The desk app connects to the proxy's data API over your network and shows it: the radio's state, every node heard, the mesh as a graph, the channels, and chat windows to write in. It talks only to the proxy, never to the radio directly.

Optional mcproxy is the main program and works on its own, with its console and commands. The desk app is an extra view of the same data. The official MeshCore apps can connect to the same proxy on port 5000 at the same time.

Features

Live overview

The companion's battery, noise and link, the apps connected, the proxy's store and queue.

Every node

A page per node: signal, adverts, routes, a repeater's stats, health and neighbours.

Connect

The app opens its Connection & settings page on first start, and whenever a certificate needs confirming. The address, token and trusted certificate are kept for later sessions.

  1. Get the address and fingerprint on the proxy machine

    mcproxy api

    Shows the address (e.g. https://192.168.1.50:5080/api/v1), the certificate fingerprint and whether a token is set. The proxy side is in the proxy guide, tab "Apps & API".

  2. Enter it on your computer

    On the Connection & settings page (the sliders icon at the top right, or the address pill), in the Proxy card: API address https://192.168.1.50:5080, and the token only if the proxy sets [api] token. Then Connect (or Enter).

    The card then shows Connected and "mcproxy <version> · API v1 · radio connected (<node name>)".

  3. Verify the certificate

    On the first connection the app shows the certificate's fingerprint. Compare it with the one from step 1, then Trust and connect. The app pins it for that address.

    Changed fingerprint If the app later reports "The proxy's certificate changed", it shows the fingerprint shown now and the one trusted before. Select Trust the new certificate only after reinstalling the proxy or renewing its certificate. Otherwise, another device is answering at that address: select Cancel.

Language

The app comes in English and French and follows the system's language; the list in the This app card chooses another one. The proxy's log is always in English.

Add a language asks for its code (de, pt-BR) and its own name. Create makes locales\de\desk.ftl next to the app, with the English texts, and opens its folder. Translate the text after each =, keep the names before it and the { $variables }, then choose the language in the list. After a change to the file, choosing it again reads it again. A file already there is never overwritten; a file made by someone else goes to the same place.

The file is plain UTF-8 text of at most 1 MB. A text that is missing, has a mistake or is far longer than the English one shows in English. The card says how many texts are missing and which lines were not understood. A regional language such as pt-BR takes from pt what it lacks.

The English model The app writes locales\en\desk.ftl at each start, to translate from. Changes to it, or a fr file there, are not used.

Console

Repeaters and sensors take commands, not chat messages. The console is for nodes you administer, and for room servers, whose chat stays separate. On the node page of a contact, Log in as guest uses a blank password and the node answers with the role it gives; on a room server, leave the field empty first: a member of the room gets in without a password, and any password skips its list. If that gets no answer, the field fills with hello, the usual guest password, for the next try. On a repeater or sensor, a blank guest login with no answer opens the admin password box. Log in as admin asks for its password. A login is tried up to 3 times, so it can take a minute or more; the page shows the time elapsed. Once logged in, the page shows your role, what it allows, and Ask now buttons, sent only when clicked: status (repeaters and rooms), telemetry, neighbours (repeaters). Console appears once a login gave admin. The node page always shows your role from the last login, and your own nodes carry a solid key in the node list. A solid star or key means set; an outline means not set. Each command is one compact block: the command, its time and a run-again button, with the reply under it in a fixed-width font. Commands sent from other devices through the proxy appear too.

Problems

When the proxy itself may be the cause, start with mcproxy doctor on the proxy machine.

You seeDo this
Pill offlineThe proxy cannot be reached; the reason is on the pill and the Connection & settings page. The app retries every few seconds and reloads everything once the proxy answers. Pages keep the data already loaded; parts not loaded yet say "Not available while the proxy is offline".
"refused the connection" / "no answer"Check the address and port (mcproxy api on the proxy machine), that your computer and the proxy machine are on the same network, and that the proxy's [server] allow lets your computer in.
"answers, but not as an mcproxy"Something else is at that port: the data API is 5080, not 5000.
"The proxy's certificate changed"Trust it only if you reinstalled the proxy or renewed its certificate. Otherwise Cancel.
Token refusedEnter the proxy's [api] token on the Connection & settings page (shown by mcproxy api).
Pill reconnectingLive updates were interrupted; the app reconnects automatically. Hover the pill for the reason.
Sidebar: radio downThe proxy lost the companion. On the proxy machine: mcproxy status, or the proxy guide's "Problems".
Message "Not sent: not in the companion's contacts"A DM needs the contact on the companion. On its node page: Put back on companion, or wait for its next advert.
"its channels are still being read"Just after the companion connects. Try again in a moment.
"several contacts match"The name or key does not tell which contact is meant: nothing was sent or deleted.
DM "Not delivered"They may not have you in their contacts, or the path broke: use Send again then Flood under the message, or Change the route.
Console: "No reply in time" / "The companion did not answer"The command may have run on the node. The app does not send it again by itself, because the node would run it twice. Check with a read command such as clock or get tx, then use the run-again button if it is still needed.
No Console button on a nodeThe console needs an admin login. On its node page, use Log in as admin with the node's password.
Console: no command lineThe last login gave a role other than admin. Log in again with the admin password.
Login: "No answer after 3 tries"The password is wrong, or the node is out of range. A node sends nothing back for a wrong password, including a blank guest login when its guest password is set, so the app can only say so after the last try. Check the password and the route, and try again. On a room server, a blank login with no answer means you are not on its list or it is out of range: try its guest password.
"(text no longer kept)" / "(text stored, but its key is not available)"The proxy dropped old texts, or runs without its message key. See the proxy guide.
Terrain tiles could not be downloadedNo internet on your computer. The other views still work.
"Settings not saved"The app can't write its settings file: the Connection & settings page's About shows where it is. Put the app where you can write, or make that file writable.
"Language file not found or not usable" / "This language file is not usable"The file named there is missing, larger than 1 MB or not UTF-8 text: put it back, or choose another language (see Language).
"needs a newer mcproxy"The app uses something this proxy does not serve yet: update the proxy (proxy guide, tab "Update").
