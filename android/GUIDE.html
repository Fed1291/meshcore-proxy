mcproxy for Android

Android client for the mcproxy data API: channels, direct messages, contacts and regions of the MeshCore companion that mcproxy shares.

Overview

The app connects to the proxy's data API (HTTPS, port 5080). It does not connect to the radio: it displays the data the proxy relays and stores, and sends messages through the proxy. The radio stays connected to the proxy while the phone connects and disconnects.

Optional mcproxy is the main program and works on its own, with its console and commands. The Android app is an extra view of the same data on the phone. The official MeshCore apps can connect to the same proxy on port 5000 at the same time.

Features

Chats

Channels (public, hashtag, private) and direct messages, live, with replies, links and delivery status.

No duplicate sends

Each message has one id. After a network error the app repeats the request with the same id; the proxy sends each id once.

Contacts

Every node the proxy knows: search, filters, a card per contact with its route and key.

Regions

See and set the region of each channel, and ask the repeaters near you which regions they serve.

Node console

Log in to repeaters, sensors and room servers, send commands, and read what they report.

Notifications

Per chat: all messages, mentions only, or none. Optionally while the app is closed.

Appearance

Material You on most phones, One UI on Samsung; light and dark follow the phone. Optional Swiss red accents.

Connect

Required once per proxy. The app stores the connection and reconnects automatically.

  1. Get the address and fingerprint on the proxy machine

    mcproxy api

    The output lists the address (e.g. https://192.168.1.50:5080/api/v1), the certificate fingerprint, and whether a token is set.

  2. Enter the address on the phone

    FieldValue
    API addressFor example https://192.168.1.50:5080. Without a scheme, the app adds https://; a trailing /api/v1 is accepted. Use http:// only when the proxy runs without TLS; the app then shows that the connection is not encrypted.
    TokenRequired only when the proxy sets [api] token. Otherwise leave it empty.

    Tap Connect.

  3. Compare the fingerprint on the phone

    On the first connection the app shows "Is this your proxy?" with the certificate fingerprint. Compare it with the fingerprint from step 1. If they match, tap Trust and connect. The app pins the certificate; afterwards only that certificate is accepted at this address.

    Changed certificate The app shows "The proxy's certificate changed" when a different certificate answers. Tap Trust the new certificate only after reinstalling the proxy or deleting its key. Otherwise, another device is answering at that address.
Public certificates A certificate signed by a known authority is accepted without the fingerprint step.

The proxy settings (port, token, allowed addresses) are described in the proxy guide, tab Apps & API.

Companion channels

The proxy sets channels on the companion on request only. A new channel goes in the companion's first empty slot; an existing channel is never replaced. Removing a channel empties its slot; you then choose whether its messages are deleted from the proxy or kept.

Under each message

The line under the last message of a run (messages from one sender a few minutes apart), and under a direct message that was not delivered. Each item can be turned off in Settings › Under each message. The message sheet always shows all details.

ItemMeans

HopsHow many repeaters it came through (direct = none).
Signal (SNR)How clearly your radio heard it.
Copies heardHow many copies arrived (the same message through other repeaters). Off by default. Tapping the count lists who passed each copy on, strongest first, with signal, RSSI and hops; tapping a row opens that node when the app knows it.
📍 RegionThe region it was sent to: its name, or ? for a region the proxy doesn't know.
Your channel messages✓ sent, no repeater heard yet; ✓✓ heard forwarded by repeaters, with 📡 the number of repeaters (the "Repeaters" item). Tapping the number lists them, strongest first, with signal, RSSI, hops and time per copy. When no repeater was heard passing it on after 30 seconds, a No repeater heard pill with Send again appears on the message, for 10 minutes after it was sent. It sends the very same packet: radios that already have it ignore it, so nobody sees it twice.
Not known if sentThe companion did not answer when it was given the message (sent here or by another app): it may have gone out or not. It changes by itself when that becomes known. Send again is offered as for a message that was not delivered (channel: not heard).
Your direct messagesShown even when the other items are off: 🕒 sending, ✓ waiting for the recipient's ACK, ✓✓ delivered. Not delivered becomes a pill on the bottom edge of the message, with a Send again button. A direct message sent from another app is not followed after a minute. Its first tap shows Direct and Flood beside it; tapping one of the three sends it that way, tapping anywhere else hides them. Send again uses the path stored for the contact (after 3 failed tries that path was reset, so it goes by flood); Direct goes straight to the contact, through no repeater, so only when it is in range; Flood goes through every repeater. Each is another try of the same message, so the chat keeps one message: the pill shows Sending… at once, and a refusal is explained under the message. If only the ACK was lost, the recipient's app may still show it twice; the (i) in the pill says so. A message whose text is no longer kept on the proxy has no pill: it can't be sent again. Small dots show the proxy's send attempts (it retries as the MeshCore app does).

Tapping a message

A long press opens a quick menu: Reply (channels), Copy, Details, Delete. A tap opens the message sheet: sender and time, the Reply / Copy / Delete tiles, then the details: for your direct messages the delivery state, route and tries; for your channel messages the repeaters heard; for a message that came through repeaters a closed row with the hop count and signal. Opening that row shows the path from top to bottom, from the first repeater to you, one pill per node with its id: solid in the app's accent colour when the name is sure, dashed when it is likely, amber and dashed with "?" when it is a guess, grey and dashed with only its id when the name is unknown. Copies heard open the same way: one row per copy, with a stripe in the colour of its signal, the repeater and time, then its signal and hops.

Scope of Delete and Clear Delete asks first, then deletes the message from the proxy, for every app; it cannot be undone. A message the proxy never stored goes from this app only. Clear in the chat menu only hides messages in this app; "Show cleared messages again" restores them. Messages deleted by any app disappear from this one too, with their notifications.

Replying

In a channel, tap the sender's name above their messages, or Reply in the message sheet. A bar above the input field shows the recipient (✕ cancels). The message is sent starting with @[Name] (the MeshCore reply format); the bubble shows "to Name" and, faded above it, the message it answers (the sender's last message before it).

Links in messages open in the browser.

Sending

Under the field, once text is typed: bytes used / limit (amber from 90 %, red above the limit, and Send is then off). A direct message holds 160 bytes. A channel message goes out as "<your node name>: text", so its limit is 160 minus the length of your node name and 2. In a direct message, a long press on Send (with text to send) offers Auto send (via the current path), Send direct (no repeater) and Send flood (via all repeaters), as in the MeshCore app. Direct and flood stay on the companion for later messages. The line above the field shows the route to the contact, with repeaters by name. Change opens a sheet: Flood, Direct, and up to three Suggested routes through repeaters, worked out from the links the proxy heard over the last 30 days, the ways the contact's adverts reached you, and how your own direct messages really fared on each route (how many were acknowledged). A route already used says so ("8 of 10 DMs ACKed this way"); measured results weigh more the more there are. Only repeaters heard in the last 3 days are used. Each suggestion says why it is offered (most reliable, a backup with another first repeater, fewest hops, next best), its estimated round-trip chance (the message there and its acknowledgement back), its hops, its weakest link, how often the contact's adverts came that way, and how many of its repeater ids other repeaters share (they would all pass the message on). A tick marks the route in use. Picking one sets it on the companion. Why it helps: the companion keeps whichever path reached the contact first, not the most reliable one, and a direct message stops at the first repeater that misses it.

Regions

A region limits a channel message to the repeaters that serve it, which reduces traffic in distant areas. The companion has one default region; a channel can have its own. The proxy stores the channel's region and applies it to every message sent through the proxy. A tap on the region under the channel name changes it from a menu; the full region sheet opens with More… in that menu, or a tap on the channel name:

ChoiceMeans
Like the companionFollows the companion's default region (shown under it, or "no region set on the companion").
No regionEvery repeater forwards the message. Unavailable when the companion's firmware does not support it.
A region chipThe regions the proxy knows, grouped by the repeaters that serve them ("Served by …"). The filled chip with a tick is the channel's region.
Region nameLower-case letters, digits and -, up to 29 characters (e.g. eu-se; a leading # is removed). Confirm with Use.
Ask the repeaters near youThe proxy discovers the repeaters in direct range (about 10 s), then asks each one which regions it serves. The results are added to the chips.

A choice is shown after the proxy confirms it. If the companion rejects a channel's region when a message is sent, the message is sent in the companion's region.

Repeaters not asked The proxy asks only repeaters whose route on the companion is already direct; it does not change routes for this. The sheet shows how many were skipped.

Stats

The third page of the bottom bar: how the mesh around your companion is doing, read from the proxy. Pick the time span at the top (1 h, 24 h, 7 days, 30 days); pull down to read it all again. Each time span is read once and kept while the app runs. While the Stats tab is on screen, new packets and messages are added as they come (the line at the bottom says "Live"); on another tab, in another app or with the screen off, nothing is read for Stats, and coming back reads only the minutes missed. Over a long session the averages, "Heard through" and "Conversations" can drift a little from the exact figures; pulling down makes them exact. It only reads; it never sends anything.

Stats has pages, as tabs under its title (swipe left or right to move between them). The time span picked applies to every page. A card with a › in its title opens its page.

Node console

Repeaters, sensors and room servers take commands, not messages. Open Node info from the node's card. The console appears only after a login that gives admin; no node is assumed to have you on its admin list. Repeaters and sensors do not appear in Chats; a room keeps its chat, and this is an extra screen.

Problems

Message or stateCause and action
"Could not connect"The reason follows (refused, no answer in time, name not found, network unreachable). Check the address and port (mcproxy api on the proxy machine), that the phone is on the same network, and that the proxy is running.
"The proxy wants a token, or this one is wrong"Enter the token set in the proxy's [api] token.
"does not allow this phone's address"The proxy's [server] allow list does not include the phone's network (e.g. add 192.168.1.0/24).
"answers, but not as an mcproxy"Wrong address or port: the API uses 5080, not the radio port 5000.
The proxy's certificate changedAccept it only after reinstalling the proxy or deleting its key (see Connect).
Dot connecting / offlineThe app reconnects automatically and reloads missed messages once the link is back (for example after a Wi-Fi drop or a proxy restart). The status card's connection details give the reason.
radio not connectedThe proxy has lost the radio; messages cannot be sent. See the proxy guide, tab Problems.
A channel is missingIt is not on the connected companion. Add it with Add a channel in the Channels tab (a private channel needs its key).
"The companion has no empty channel slot"Remove a channel from the companion first (chat menu).
"Not changed: the proxy is still reading the companion's channels…"Try again in a moment. If it stays: the proxy stores no messages and no app is connected to its MeshCore port, and messages waiting on the companion would be lost. Connect an app there, or turn on the proxy's message store.
"Not sent: the companion is busy"Its packet queue stayed full, or its channels are still being read. Try again in a moment.
"Not deleted: several contacts' keys start the same way"The contact's full key is not known, so nothing was deleted. Delete the messages one by one (tap a message, Delete).
"Too late to send it again"Over 10 minutes after sending, radios no longer remember the packet. Send it as a new message.
Login: "No answer after 3 tries"A wrong password, or the node is out of range: a node sends nothing back for a wrong password. On a repeater or sensor, a blank guest login with no answer can also mean it has a guest password.
No Message button on a contactThe node is not in the companion's contacts, or it is a repeater or sensor (use Node info, or Console after an admin login). MeshCore direct messages require both sides to have each other as contacts.
No notificationsIn Settings › Notifications, check that notifications are allowed and the level is not None. For a closed app, turn on Keep listening when the app is closed.
📍 ? under messagesThe message was sent to a region the proxy does not know. In a channel's region sheet, ask the repeaters near you or enter the region name.
"This companion's firmware has no regions"Regions require a newer companion firmware.
