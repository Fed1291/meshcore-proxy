mcproxy guide · Windows

Share one MeshCore companion radio with every app on your network, and keep a history of everything it hears. The proxy runs on a Windows PC with the radio on Bluetooth, on a USB cable or on your network (TCP).

Overview

A MeshCore companion radio talks to one app at a time. mcproxy runs on a Windows PC with the radio on Bluetooth or a USB cable, or reaches it over the network (TCP) when its firmware has Wi-Fi or Ethernet. It holds that one connection and lets any number of MeshCore apps connect to it over your network (TCP port 5000), as if each had the radio to itself.

Any MeshCore app connects on port 5000 The official MeshCore apps, meshcore-cli, the Home Assistant integration, and anything else that speaks the MeshCore companion protocol over TCP connect to the proxy PC's IP address on port 5000, exactly as they would connect to a Wi-Fi companion on the network. Nothing to install in the app, no special mode. Several apps can be connected at once. .\mcproxy status (the console's Status tab) shows the address to use; the port is set by [server] listen. The data API on port 5080 is separate: it serves the apps built around the proxy (mcproxy desk, mcproxy for Android), web pages and scripts.
mcproxy is the main program and works on its own: its console shows the radio, the nodes, the mesh, the history and the logs, and has a chat to read and write messages; the mcproxy commands do the rest. The mcproxy desk and Android apps are optional extras that show the same data in a window or on a phone.

Features

Many apps at once

Phone, tablet and desktop connected together; each sees every message.

Message history

Stored encrypted: an app that was offline gets what it missed when it reconnects.

Mesh observer

Every packet heard is recorded: who is out there, through which repeater, at what signal, in which region.

Auto-reconnect

The radio link comes back by itself after a drop, unplug or reboot.

Live console

A full-screen terminal view: radio, nodes, mesh, history, logs and chat.

Data API

HTTPS + live events for the mcproxy desk and Android apps, web pages and scripts.

Install

Nothing is installed in Windows itself: the program, its config and its data stay in one folder. Each step can be reverted; see Remove.

  1. Put the files in a folder

    Copy the folder (mcproxy.exe, GUIDE.html, API.md) to a place your user can write to, e.g. C:\mcproxy. Not under C:\Program Files: mcproxy writes its config, database and logs next to the program.

    If Windows shows "Windows protected your PC" the first time: More info, then Run anyway.

  2. Get the radio ready

    USB: connect the companion with a USB data cable. Close anything that holds its port: the web flasher, a serial monitor, another MeshCore program. In most cases Windows installs the USB driver by itself. If Device Manager shows the board without a COM port, install the USB-serial driver of its chip (CP210x or CH34x).

    Bluetooth: switch Bluetooth on (Settings → Devices → Bluetooth). The companion takes one Bluetooth connection: disconnect your phone from it, and stop any other program that uses it.

  3. Open PowerShell in the folder in PowerShell

    In File Explorer, open the folder, then File → Open Windows PowerShell (or Shift+right-click in the folder, "Open PowerShell window here"). Or:

    cd C:\mcproxy

    Windows Terminal shows the console best; the classic PowerShell window works too.

  4. Setup: find the radio in PowerShell

    .\mcproxy setup
    Radio onWhat setup does
    USB cableLooks here first: checks the COM ports, shows the companion it finds with its name and asks whether to use it over USB. Nothing to pair. With several radios plugged in, it asks which one; --usb COM5 takes that port without asking.
    BluetoothWhen no companion is used over USB: shows the Bluetooth adapter, scans, lists each companion with its signal, asks for the PIN (the one on the companion's screen, else the MeshCore default 123456) and pairs. --ble skips USB; --address AA:BB:CC:DD:EE:FF skips the scan and --pin the question.
    Network (TCP).\mcproxy setup --tcp 192.168.1.60 (add :port when not 5000, or give a name). Setup asks the companion who it is and saves its address. Give it a fixed address in the router (DHCP reservation). It serves one client at a time: the apps connect to mcproxy, never to the companion itself.

    Setup saves the choice in config\config.toml.

    Same Windows account A Bluetooth pairing belongs to the Windows account that ran setup: run the proxy as that account.

  5. Start and check in PowerShell

    .\mcproxy run

    The proxy runs as long as this window stays open; Ctrl+C stops it. The first time, Windows Firewall asks whether mcproxy may use the network: allow it on private networks, so apps on other devices can connect.

    In a second PowerShell window, in the same folder:

    .\mcproxy status

    The console opens on its Status tab: you should see ● radio connected and the address apps use. q quits (the proxy keeps running).

  6. Connect your apps

    AppConnect to
    MeshCore appsTCP/IP, the address from step 5, e.g. 192.168.1.50 port 5000.
    mcproxy desk, AndroidThe data API: see the tab Apps & API.

  7. Run it in the background as administrator

    Optional: instead of keeping a window open, Windows starts mcproxy by itself at every start of the PC, with no window and before anyone logs in (a scheduled task, the Windows counterpart of a service). First stop the proxy from step 5 (Ctrl+C in its window).

    Open PowerShell with Run as administrator, with the same Windows account that ran setup (the message key is in that account's profile, and a Bluetooth pairing belongs to that account). Go to the folder, then paste the whole block:

    cd C:\mcproxy
$exe = (Resolve-Path .\mcproxy.exe).Path
$action = New-ScheduledTaskAction -Execute $exe -Argument run -WorkingDirectory (Split-Path $exe)
$trigger = New-ScheduledTaskTrigger -AtStartup
$user = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType S4U -RunLevel Limited
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1)
Register-ScheduledTask -TaskName mcproxy -Action $action -Trigger $trigger -Principal $user -Settings $settings
New-NetFirewallRule -DisplayName mcproxy -Direction Inbound -Program $exe -Action Allow -Profile Private
Start-ScheduledTask mcproxy
    PartWhat it does
    -AtStartup, S4UStarts at every start of the PC, as your account, whether you are logged in or not. No password is stored.
    -ExecutionTimeLimit 0Runs without a time limit (by default Windows stops a task after 3 days).
    -AllowStartIfOnBatteries …Keeps it running on a laptop on battery.
    New-NetFirewallRuleLets apps on other devices reach the proxy (a background task gets no firewall question). -Profile Private: only on networks set as private.

    Check, in a normal PowerShell window in the folder: .\mcproxy status. The commands to stop, start and remove the task are in Commands.

    Sleep A PC that sleeps stops the proxy. Set Settings → System → Power → Sleep to Never when plugged in.
Changing the radio After replacing the radio, or moving it to another USB port, run .\mcproxy setup again (with the proxy stopped).

Commands

in PowerShell In the mcproxy folder, type each command as .\mcproxy … (in Command Prompt: mcproxy …). .\mcproxy <command> --help describes each one.

Look

CommandShows
mcproxy statusThe console, Status tab: radio link, battery, connected apps, live activity.
mcproxy nodesThe console, Nodes tab: every node heard. --hours 24, --type repeater.
mcproxy meshThe console, Mesh tab: traffic by type and hour, the repeaters you hear through.
mcproxy historyThe console, History tab: your radio over time (battery, temperature, noise, packets).
mcproxy history <name>One node: its adverts, signal, status and telemetry.
mcproxy watchEvery frame and event, live, as plain lines (--hex adds the bytes). Ctrl+C stops.
mcproxy logsThe proxy's log (the files in logs\). -f follows, -n 200 lines, --apps, --radio, --problems, --grep <text>. --purge-own removes the lines about messages your node sent from the log files (asks first).
mcproxy contactsThe radio's contacts: type, last advert, path, distance.
mcproxy doctorChecks everything (config, Bluetooth or USB, pairing, proxy, link) and gives hints.

Add --plain to a console command for plain text (handy to copy or pipe), --json to status for raw data.

Messages

CommandDoes
mcproxy send --channel Public hiSends a channel message; --to <name> for a direct message. Sent once, never repeated. A channel message goes out once the companion has confirmed which slot holds that channel; for a channel that is not on the companion it is refused.
mcproxy mirrorCopies of what one device sends, for your other devices: mirror channel on|off, mirror dm on|off.
mcproxy text own hide|showWhether the text of messages your node sends shows in the console, watch, log and API.
mcproxy polite on|offPolite sending, on by default, for all apps together: up to 4 commands that go on air (messages, adverts, requests to repeaters) go out at once, then one every 3 s; at most 6 DMs wait for their ACK at once (the companion recognises 8); the exact same message sent twice goes out once. Nothing is refused: a command waits its turn. Manual resends and DM retries always go out. off = everything goes out as it comes. [polite] in the config sets the numbers.

Radio and contacts

CommandDoes
mcproxy reconnectDrops the radio link and reconnects now. With serial_port = "", it also asks the other COM ports again.
mcproxy kick <id>Disconnects one app (its id is in mcproxy status).
mcproxy track add <name>Asks a repeater, room server or sensor (a contact of the companion) for its status and telemetry regularly; track remove stops.
mcproxy prune --days 30Removes contacts the radio hasn't heard for 30 days (favourites stay). Lists them and asks first; --auto 30 does it daily.
mcproxy contacts --overwrite-oldest on|offWhen the radio's list is full: replace the oldest contact, or add nothing (the radio's own setting).
mcproxy channelsThe radio's channels. channels add "#name" adds a hashtag channel, channels add Name --key <32 hex> a private one, channels remove <name|id|slot> removes one (its messages stay; with --delete-messages they are deleted from the proxy too). A channel is its key: removed and added again, it is the same channel in any slot, with its messages.
mcproxy login <name>Logs in to a repeater or room server and shows your role (admin, read-write, read-only or guest). Blank works when the node has you on its access list, or has a blank guest password; otherwise --password <password>. The password is kept nowhere. Guests can read status, basic telemetry, neighbours and owner info, not run commands.
mcproxy cli <name> <command>Runs a command on a repeater, room server or sensor and prints its reply, e.g. mcproxy cli "Hilltop Rptr" ver. It needs an admin role and goes out once: when no reply comes it may still have run. mcproxy cli --list shows the commands.
mcproxy backup / restoreWhat the proxy saved (contacts, channels), and putting it back on the radio after a reflash or reset. backup --keys on also keeps the channels' secret keys (encrypted), so restore can recreate private channels; restore --contacts or --channels puts back only one part.

Data

CommandDoes
mcproxy retentionHow long data is kept, and the database size. Options change it (lowering deletes older data right away).
mcproxy resetStart over: wipes what the proxy gathered (--messages, --mesh, --contacts, --history or --all). Shows what goes and asks you to type yes. The radio and the config are never touched.
Each companion has its own data: connecting another one sets the current data aside and starts empty; the previous companion gets its own data back when it is connected again. reset wipes the connected companion's data.
mcproxy syncWhat a MeshCore app on port 5000 gets when it comes back: messages of the last 2 days, and of those the newest 200 of each channel, so an app is not flooded after days away. DMs are not capped per channel. --days 7 --per-channel 500 changes it, 0 = no limit. What is left out stays in the proxy (console, desk, Android) but never reaches that app. A device seen for the first time starts 24 hours back.
mcproxy apiThe data API's address, certificate fingerprint and token (see Apps & API).

Setup, Bluetooth and USB

CommandDoes
mcproxy setupGuided setup (see Install). The proxy must be stopped.
mcproxy runRuns the proxy in this window, until Ctrl+C.
mcproxy adaptersThe Bluetooth adapter Windows gives to programs.
mcproxy scanEvery MeshCore companion it can find: over Bluetooth (--all: every device), and on the COM ports, with the board each USB id points to. The one mcproxy uses shows as "in use".
mcproxy pair / unpairPair or forget the Bluetooth companion by hand, for this Windows account (stop the proxy first).
[radio] serial_portIn config\config.toml. "" = the companion is found by itself: the port that answered last, then the boards known to run MeshCore. Other serial ports are asked only when there is no such board, 3 times each, then again after they are plugged in anew or after mcproxy reconnect.

Language

The console, the commands and their --help come in English and French and follow the language Windows is shown in. In every language, the log, the data API, the names of commands and options and part of the command output are in English.

CommandDoes
mcproxy languageLists the languages and marks the one chosen.
mcproxy language frAlways uses that language; auto = the one of Windows. Saved as [ui] language in config\config.toml. In the console, l on the Status tab changes to the next one; a console already open elsewhere takes the change when it is opened again.
mcproxy language new deAdds another language: makes config\locales\de\mcproxy.ftl with the English texts, to translate. A file already there is never overwritten.

In that file, translate the text after each =, keep the names before it and the { $variables }, and put the language's own name in language-name. Then mcproxy language de. A file made by someone else goes to the same place. It is plain UTF-8 text of at most 1 MB. A text that is missing or has a mistake shows in English; once the language is chosen, mcproxy language names the lines with a mistake. A regional language such as pt-BR takes from pt what it lacks.

The English model The proxy writes config\locales\en\mcproxy.ftl when it starts, to translate from. Changes to it, or a fr file there, are not used.

The background task

Only if you set it up (Install, step 7). Start and stop work in a PowerShell window as administrator:

Stop-ScheduledTask mcproxy                      # stop (before setup or an update)
Start-ScheduledTask mcproxy                     # start
Stop-ScheduledTask mcproxy; Start-ScheduledTask mcproxy   # restart (after a config change)
Get-ScheduledTask mcproxy                       # is it running? (State: Running)

The same in the Task Scheduler window: Task Scheduler Library, mcproxy, then End / Run.

Console

A full-screen terminal view, refreshed live. mcproxy status, nodes, mesh and history each open it on the matching tab.

The Status tab needs the proxy running; the other tabs read the database directly, so they work even when it's stopped. Quitting the console never stops the proxy.

Apps & API

AppPortHow
MeshCore apps, meshcore-cli, Home Assistant5000Their usual TCP connection: the proxy speaks the radio's own protocol.
mcproxy desk, Android, web pages, scripts5080The data API: HTTPS + live events, with the history the proxy keeps. Every endpoint is described in API.md, next to this guide.

  1. Get the address and fingerprint in PowerShell

    .\mcproxy api

    Shows the address (e.g. https://192.168.1.50:5080/api/v1), the certificate fingerprint and whether a token is set. The proxy makes its own certificate on first start.

  2. Connect the app

    Enter the address in the app (on your computer the desk app, on the phone the Android app). On the first connection the app shows the certificate's fingerprint: compare it with the one from step 1 and accept it. The app remembers it.

    The desk app on the same PC as the proxy can use https://127.0.0.1:5080/api/v1.

    Changed fingerprint Accept a new fingerprint only after reinstalling the proxy or deleting its key. Otherwise, another device is answering at that address.

Settings

In config\config.toml (in the mcproxy folder), section [api], then restart the proxy (Ctrl+C and .\mcproxy run, or restart the background task):

SettingDefaultMeaning

listen0.0.0.0:5080Where it answers.
token""Empty = no token. Set one to ask every app for it.
[server] allow[]Empty = everyone, or e.g. ["192.168.1.0/24"]: who may connect (both ports).

Update

An update replaces the program file only. Configuration and data are kept.

  1. Stop the proxy

    Windows cannot replace a program that is running. Ctrl+C in its window, or, for the background task, as administrator:

    Stop-ScheduledTask mcproxy

  2. Replace the program

    Copy the new mcproxy.exe over the old one in the mcproxy folder. A new GUIDE.html or API.md replaces the old one. The background task and the firewall rule point to the file by its path: they keep working.

  3. Start again

    .\mcproxy run, or as administrator:

    Start-ScheduledTask mcproxy

    Then check with .\mcproxy status.

New settings are added to your config with their defaults when the new version starts; existing values are never changed.

Remove

Each step reverts one installation step. Run them in order, or only those you need.

  1. Forget the companion in Bluetooth in PowerShell

    Only for a Bluetooth companion, with the proxy stopped, as the Windows account that ran setup:

    .\mcproxy unpair

    Or Settings → Devices → Bluetooth, the companion, Remove device.

  2. Remove the background task and the firewall rules as administrator

    In the mcproxy folder. This also removes the rule Windows made when it asked about the firewall.

    cd C:\mcproxy
Stop-ScheduledTask mcproxy -ErrorAction SilentlyContinue
Unregister-ScheduledTask mcproxy -Confirm:$false -ErrorAction SilentlyContinue
Get-NetFirewallApplicationFilter -Program (Resolve-Path .\mcproxy.exe).Path | Get-NetFirewallRule | Remove-NetFirewallRule

  3. Delete the folder

    With the proxy stopped, delete the mcproxy folder: program, guide, config, database and logs are all in it. To keep a language you translated, copy its folder from config\locales\ first.

    cd \
Remove-Item -Recurse C:\mcproxy

  4. Delete the message key and the API certificate in PowerShell

    As the Windows account that ran mcproxy:

    Remove-Item -Recurse "$env:APPDATA\mcproxy"
    Without the key, the stored message texts can never be read again. The apps will ask you to accept a new certificate after a reinstall.
Nothing else to undo: nothing is installed in Windows and no system setting is changed.

Problems

in PowerShell .\mcproxy doctor checks the configuration, Bluetooth or the USB port, the pairing, the proxy and the radio link, and suggests a fix for each problem.

.\mcproxy doctor
.\mcproxy logs --problems
You seeDo this
"Bluetooth is switched off", "disabled"Settings → Devices → Bluetooth: switch it on. Check airplane mode, a Bluetooth switch on the PC, and that a USB dongle is plugged in.
"Windows does not let programs use Bluetooth"Settings → Privacy → Radios: let apps use it. "Turned off by a policy": the PC's administrator decides.

Bluetooth: "the companion no longer knows this pairing"The proxy pairs again by itself after two attempts. If the message stays, that did not work: .\mcproxy unpair with the proxy stopped, then .\mcproxy setup.
